# Git Atlas

Git Atlas 是一个面向 Git 初学者的四区可视化学习工具。你可以在网页终端中输入 Git 风格命令，并实时观察工作区、暂存区、本地仓库和远程仓库之间的变化。

应用以 `index.html` 为入口，样式和脚本按职责放在 `assets/` 中，不需要后端、构建工具或系统 Git。保留完整目录即可离线使用，不能只复制入口文件。

## 快速开始

1. 下载或克隆本项目。
2. 双击打开项目根目录的 [`index.html`](../index.html)。
3. 在终端输入 `git status`，开始观察四个区域的状态。

建议使用较新版本的 Chrome、Edge、Firefox 或 Safari。

## 主要功能

- 四区实时对照：工作区、暂存区、本地仓库和模拟远程仓库同步展示文件树与状态。
- 文件工作台：支持新建、编辑、重命名、移动和删除工作区文件。
- Git 风格终端：支持引号与参数解析、上下键历史、Tab 补全、语法配色和内部滚动。
- 分支地图：横向展示提交 DAG、父子关系、分支、标签、远程引用和当前 HEAD。
- 提交检查：点击提交节点可查看作者、时间、父提交、变更文件及提交前后内容对比。
- 学习资料：13 个主题章节，配有独立可反复运行的可视化示例。
- 命令参考：按命令查看语法、作用、示例、常见误区和操作提示。
- 命令历史：支持搜索、复制、重新执行，并查看每次执行的结果与说明。
- 仓库信息：查看和模拟配置 `user.name`、`user.email` 与远程仓库地址。
- 本地持久化：仓库状态、历史、主题和学习进度保存在浏览器 `localStorage` 中。
- 响应式界面：支持亮色、暗色主题以及桌面和移动端布局。

## 支持的命令

| 类别 | 命令 |
| --- | --- |
| 基础流程 | `init`、`status`、`add`、`commit`、`diff`、`log`、`show` |
| 身份配置 | `config` |
| 分支与历史 | `branch`、`checkout`、`switch`、`merge`、`cherry-pick`、`revert`、`reflog` |
| 撤销与文件 | `reset`、`restore`、`rm`、`mv`、`stash`、`tag` |
| 远程协作 | `remote`、`fetch`、`pull`、`push`、`clone` |
| 帮助 | `help` |

在页面终端中运行以下命令，可以查看当前模拟器支持的准确范围：

```bash
git help
git help commit
git help --all
```

## 推荐体验流程

默认示例仓库已经初始化，并配置了模拟远程仓库。可以按顺序尝试：

```bash
git status
git diff
git add README.md
git commit -m "更新项目说明"
git log --oneline --graph --all
git push
```

每执行一步，都可以对照四区内容、分支地图和命令说明，理解数据实际流向。

## 常用操作

| 操作 | 方式 |
| --- | --- |
| 执行命令 | `Enter` |
| 浏览历史命令 | `↑` / `↓` |
| 补全命令 | `Tab` |
| 清空终端显示 | `clear`、清除按钮或 `Ctrl/Cmd + L` |
| 新建文件 | 工作区右上角“新建文件” |
| 编辑或重命名文件 | 点击工作区文件或其编辑按钮 |
| 查看提交 | 点击分支地图中的提交节点 |
| 重置仓库 | 页面右上角“重置”，选择“默认模板”或“空模板” |

清空终端只会隐藏当前终端输出，不会删除命令历史或修改仓库。

重置时，“默认模板”会恢复带示例文件、提交和模拟远程的练习仓库；“空模板”会创建一个未执行 `git init` 的空目录，不包含文件、提交、远程或命令历史。两种方式都会保留主题、学习进度以及全局姓名和邮箱配置。

## 分支与未提交文件

分支记录的是提交，不是独立的工作目录。`checkout -b` / `switch -c` 从当前提交创建分支时，会保留未提交的暂存和工作区修改。切换已有分支时，未受目标提交影响的修改可以一同保留；如果会覆盖暂存内容、工作区修改或未跟踪文件，命令会拒绝执行并保持原状态。

在 `feature` 上新建但尚未提交的文件，切回 `main` 后仍可能出现在工作区，这与真实 Git 的共享工作区一致，并不表示文件已经进入 `main`。要让文件成为 `feature` 的版本，应在 `feature` 上执行 `add` 和 `commit`，再切回 `main` 对照本地 HEAD 快照。

## 数据与安全边界

- 所有 Git 行为都在浏览器中模拟，不会调用电脑上的 Git。
- 文件内容只存在于当前网页的模拟仓库中，不会写入本地磁盘。
- 远程地址仅用于教学展示，不会建立网络连接，也不会上传代码。
- 姓名和邮箱只用于模拟提交作者，不是登录账号或认证信息。
- 页面数据保存在当前浏览器中；清理站点数据会移除保存的学习状态。

## 模拟器边界

Git Atlas 聚焦常见学习流程，并不等同于完整的 Git 实现：

- 每次执行一条命令，不支持管道、重定向或系统 Shell 命令。
- `pull` 按 `fetch + merge` 的方式模拟。
- 冲突检测采用教学化的文件级三方合并，行为比真实 Git 更保守。
- 合并使用按祖先关系确定的最佳共同祖先；遇到多个最佳共同祖先时会明确拒绝，不模拟 Git 的递归合并基准算法。
- `cherry-pick` 和 `revert` 每次处理一个普通提交或根提交。
- `mv` 只支持单个文件重命名或移动到明确的文件路径，不支持目录操作；它保留原暂存内容，工作区后续编辑仍需单独 `add`。
- 无参数 `push` 将当前本地分支推送到已记录的上游目标，不模拟真实 Git 的全部 `push.default` 策略。指定分支的 `push origin main` 仍以本地 `main` 为源。
- stash 恢复遇到真正的内容或路径冲突时会整体拒绝并保留保存项，不生成真实 Git 的 stash 冲突索引。
- 不包含真实认证、SSH、`rebase`、强制推送以及 Git 的全部参数组合。

## 项目结构

```text
git-learn/
|-- index.html                 # 页面入口与静态结构
|-- assets/
|   |-- css/                   # 分区样式，按原层叠顺序加载
|   `-- js/
|       |-- engine/git-sim.js  # 命令解析、仓库状态和 Git 模拟逻辑
|       |-- ui/               # 四区、文件编辑、分支图、终端等界面
|       |-- lessons/          # 命令资料、课程和独立演示数据
|       `-- app.js            # 事件绑定与应用初始化
|-- tests/                    # 引擎回归测试、浏览器测试与旧存档样本
|-- docs/                     # README、LICENSE、协作规范与设计记录
`-- .gitignore                # 保留的隐藏配置文件
```

根目录唯一的非隐藏文件是 `index.html`；其他源码、测试与文档分别放在对应目录中。运行和静态部署需要同时保留 `index.html` 和整个 `assets/`，不需要 `tests/` 和 `docs/`。

脚本采用有序的经典 `defer` 加载而非 ES modules，因此不需要本地服务即可通过 `file:` 打开。调整脚本顺序时要注意共享状态与界面初始化依赖，`app.js` 必须最后加载。

## 修改与验证

应用本身不依赖 Node.js。运行自动化测试需要 Node.js 20 或更高版本。先在项目根目录执行：

```powershell
cd tests
npm ci
npm test
npm run test:browser
```

浏览器测试优先使用本机 Chrome / Edge；如果本机没有兼容浏览器，在 `tests/` 中运行 `npx playwright install chromium`。也可以通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定浏览器可执行文件。

- 引擎测试直接加载生产模块，覆盖分支切换、暂存与重命名、三类操作中止、共同祖先、远程引用和 stash 的成功与原子失败边界。
- 浏览器测试在独立临时上下文中同时验证 `file:` 和临时 HTTP 服务，不读取或覆盖用户的浏览器配置。
- 浏览器覆盖全部课程示例、文件操作、命令历史、提交检查、完整存档往返和旧版冲突存档的兼容恢复。
- 桌面、宽屏与窄屏的亮暗主题截图及结果写入 `tests/artifacts/`，已由 Git 忽略；测试结束时自动关闭浏览器和临时服务。

保存格式仍使用 `git-atlas-v1` 和 `version: 1`。新版冲突合并可额外记录实际使用的基准提交，旧版没有该字段的进行中操作仍可读取和中止。

修改后也可以手动检查以下流程：

1. 双击打开页面，确认没有控制台错误。
2. 执行 `git status`、`git add`、`git commit` 和 `git push`，确认四区同步更新。
3. 创建并合并分支，确认分支地图与提交详情正确刷新。
4. 刷新页面，确认仓库状态和命令历史仍然存在。
5. 检查亮色、暗色及窄屏布局。
