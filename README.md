# Git Atlas

Git Atlas 是一个面向 Git 初学者的四区可视化学习工具。你可以在网页终端中输入 Git 风格命令，并实时观察工作区、暂存区、本地仓库和远程仓库之间的变化。

整个应用封装在一个 `index.html` 中，不需要后端、构建工具或系统 Git，下载后即可离线使用。

## 快速开始

1. 下载或克隆本项目。
2. 双击打开 [`index.html`](./index.html)。
3. 在终端输入 `git status`，开始观察四个区域的状态。

建议使用较新版本的 Chrome、Edge、Firefox 或 Safari。

## 主要功能

- 四区实时对照：工作区、暂存区、本地仓库和模拟远程仓库同步展示文件树与状态。
- 文件工作台：支持新建、编辑、重命名、移动和删除工作区文件。
- Git 风格终端：支持引号与参数解析、上下键历史、Tab 补全、语法配色和内部滚动。
- 分支地图：横向展示提交 DAG、父子关系、分支、标签、远程引用和当前 HEAD。
- 提交检查：点击提交节点可查看作者、时间、父提交、变更文件及提交前后内容对比。
- 学习资料：13 个主题章节，配有独立可反复运行的可视化示例。
- 命令参考：按命令查看语法、作用、示例、常见误区和操作提示。
- 命令历史：支持搜索、复制、重新执行，并查看每次执行的结果与说明。
- 仓库信息：查看和模拟配置 `user.name`、`user.email` 与远程仓库地址。
- 本地持久化：仓库状态、历史、主题和学习进度保存在浏览器 `localStorage` 中。
- 响应式界面：支持亮色、暗色主题以及桌面和移动端布局。

## 支持的命令

| 类别 | 命令 |
| --- | --- |
| 基础流程 | `init`、`status`、`add`、`commit`、`diff`、`log`、`show` |
| 身份配置 | `config` |
| 分支与历史 | `branch`、`checkout`、`switch`、`merge`、`cherry-pick`、`revert`、`reflog` |
| 撤销与文件 | `reset`、`restore`、`rm`、`mv`、`stash`、`tag` |
| 远程协作 | `remote`、`fetch`、`pull`、`push`、`clone` |
| 帮助 | `help` |

在页面终端中运行以下命令，可以查看当前模拟器支持的准确范围：

```bash
git help
git help commit
git help --all
```

## 推荐体验流程

默认示例仓库已经初始化，并配置了模拟远程仓库。可以按顺序尝试：

```bash
git status
git diff
git add README.md
git commit -m "更新项目说明"
git log --oneline --graph --all
git push
```

每执行一步，都可以对照四区内容、分支地图和命令说明，理解数据实际流向。

## 常用操作

| 操作 | 方式 |
| --- | --- |
| 执行命令 | `Enter` |
| 浏览历史命令 | `↑` / `↓` |
| 补全命令 | `Tab` |
| 清空终端显示 | `clear`、清除按钮或 `Ctrl/Cmd + L` |
| 新建文件 | 工作区右上角“新建文件” |
| 编辑或重命名文件 | 点击工作区文件或其编辑按钮 |
| 查看提交 | 点击分支地图中的提交节点 |
| 重置示例 | 页面右上角“重置” |

清空终端只会隐藏当前终端输出，不会删除命令历史或修改仓库。

## 数据与安全边界

- 所有 Git 行为都在浏览器中模拟，不会调用电脑上的 Git。
- 文件内容只存在于当前网页的模拟仓库中，不会写入本地磁盘。
- 远程地址仅用于教学展示，不会建立网络连接，也不会上传代码。
- 姓名和邮箱只用于模拟提交作者，不是登录账号或认证信息。
- 页面数据保存在当前浏览器中；清理站点数据会移除保存的学习状态。

## 模拟器边界

Git Atlas 聚焦常见学习流程，并不等同于完整的 Git 实现：

- 每次执行一条命令，不支持管道、重定向或系统 Shell 命令。
- `pull` 按 `fetch + merge` 的方式模拟。
- 冲突检测采用教学化的文件级三方合并，行为比真实 Git 更保守。
- `cherry-pick` 和 `revert` 每次处理一个普通提交或根提交。
- 不包含真实认证、SSH、`rebase`、强制推送以及 Git 的全部参数组合。

## 修改与验证

应用的 HTML、CSS 和 JavaScript 均内联在 `index.html` 中。修改后至少检查以下流程：

1. 双击打开页面，确认没有控制台错误。
2. 执行 `git status`、`git add`、`git commit` 和 `git push`，确认四区同步更新。
3. 创建并合并分支，确认分支地图与提交详情正确刷新。
4. 刷新页面，确认仓库状态和命令历史仍然存在。
5. 检查亮色、暗色及窄屏布局。
